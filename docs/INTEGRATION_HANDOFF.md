# Integration Handoff Bundle

This document defines the minimum package of code, artifacts, commands, and
limits required before claiming Charybdis is ready for a downstream integration
exercise.

## Bundle Contents

Provide these items together:

- source revision and tag or commit SHA;
- built wheel for the same revision;
- `docs/STABLE_API.md`;
- `docs/PRODUCTION_INTEGRATION.md`;
- `docs/VALIDATION.md`;
- `docs/KNOWN_LIMITS.md`;
- replay sample generated by `record_harbor_packets()`;
- latest full validation artifact tree;
- CI run URL for the pushed source revision; and
- dependency freeze or container image identifier used for pod validation.

## Supported Verification Commands

From a clean checkout:

```bash
python -m pip install --upgrade pip
python -m pip install -c requirements/ci.txt -e ".[dev]"
python -m pytest tests/test_public_api.py tests/test_hybrid_contracts.py tests/test_hybrid_replay.py
```

For CI-equivalent local verification, use the full command set in
`docs/VALIDATION.md`.

On a prepared RunPod host with the repository at `/workspace/Charybdis`:

```bash
cd /workspace/Charybdis
bash scripts/pod/pod_integration_grade.sh
```

For release-tier evidence:

```bash
cd /workspace/Charybdis
bash scripts/pod/pod_release_grade.sh
```

These pod scripts are validation utilities. They are supported for reproducing
evidence, not for embedding in an application runtime.

## Replay Verification

Replay is the primary hardware-free integration check:

```python
from charybdis.evaluation import (
    REPLAY_SCHEMA_VERSION,
    load_replay_log,
    replay_packets,
)

log = load_replay_log("mission_replay.json")
assert log.manifest.schema_version == REPLAY_SCHEMA_VERSION
results = replay_packets(log)
```

Unknown replay schema versions are rejected. Replayers should retain the source
revision, `schema_version`, and Charybdis package version with every archived
mission log.

## Bathymetry Requirement

GEBCO characterization is useful regression evidence, but it is not
navigation-grade evidence. For integration claims, real-bathymetry validation
must be run with:

```bash
python scripts/real_bathymetry_validate.py \
  --tile path/to/navigation_candidate_tile.npz \
  --tier release \
  --runs 256 \
  --workers 31 \
  --require-integration-grade-map \
  --output artifacts/validation/<RUN>/real_bathymetry/release.json
```

`--require-integration-grade-map` rejects maps coarser than 50 metres per cell.
Passing this gate does not certify a map; it only prevents coarse public tiles
from being used as integration-grade evidence.

## Acceptance Statement

A complete handoff may say:

> Charybdis passed the declared software validation gates for the referenced
> source revision and artifact set. It exposes a stable packet-to-guidance API
> suitable for integration testing under the limits documented here.

It must not say:

> Charybdis is certified, safety-approved, field-proven, or navigation-grade in
> real water without additional hardware, map, and sea-trial evidence.
